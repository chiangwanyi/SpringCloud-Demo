## 完善 service-system 模块 + 新增 service-system-api 模块
- 目标：MyBatis-Plus 增删改查（Mapper 用注解 @Select 等，不用 XML）、加启动类与测试类；新增 service-system-api（DTO + Feign）对外提供用户信息接口。
- 结构：
  - service-system-api：com.jwy.scd.api.SysUserApi（@FeignClient + @RequestMapping，契约接口）、com.jwy.scd.api.dto.UserInfoDTO（脱敏，不含 password）。
  - service-system：entity.SysUser（@TableName sys_user）、mapper.SysUserMapper（extends BaseMapper + 注解 @Select）、service.ISysUserService/impl（extends IService）、controller.SysUserController（implements SysUserApi）、ServiceSystemApplication（@MapperScan）、SysUserCrudTest（@SpringBootTest 验证 CRUD）。
- 依赖坑（关键，环境是 Spring Boot 4.0.8 / Spring Framework 7.0.9）：
  1. mybatis-plus 必须用 **mybatis-plus-spring-boot4-starter:3.5.16**（不要用 mybatis-plus-boot-starter 3.5.3.1，会拉 mybatis-spring 3.x，与 Spring 7 的 factoryBeanObjectType 冲突报 Invalid bean definition）。
  2. 必须显式加 **com.h2database:h2**（runtime），否则 H2 驱动加载失败。
  3. service-system-api 里的 spring-cloud-starter-openfeign 设为 **<optional>true</optional>**，避免实现模块传递引入 spring-cloud 自动配置（SimpleDiscoveryClientAutoConfiguration 在 Boot 4 下条件处理崩溃）。openfeign 固定 4.1.0（本地仓库无与 Boot4 匹配的 spring-cloud BOM）。
  4. 测试用 H2 内存库（src/main/resources/schema.sql + application.yml），@SpringBootTest(webEnvironment=NONE)。
- 验证：./mvnw -pl service-system -am test → BUILD SUCCESS，Tests run: 1, Failures: 0, Errors: 0。
- 说明：测试/演示资源（schema.sql、application.yml）在本任务执行期间曾被外部进程清掉，已重建到 src/main/resources（运行与测试共用）。

  - service-auth-api：com.jwy.scd.api.auth.AuthApi（@FeignClient(name=service-auth) + @RequestMapping("/api/auth")，登录/校验/注销三个方法）、dto.LoginDTO / dto.TokenInfoDTO。为避开与 service-system-api 同包 com.jwy.scd.api 的跨 jar 分包问题，auth 契约放在 com.jwy.scd.api.auth 子包。

- 父 pom.xml <modules> 新增 service-auth、service-auth-api。

## 新增 service-gateway 模块（API 网关）
- 目标：统一对外入口，按路径路由到后端微服务。用户只访问网关 :8080；网关把 `/api/sys-user/**` 转 service-system(:8081)、`/api/auth/**` 转 service-auth(:8082)。
- Boot 4 / Spring Framework 7 专属坑（关键）：
  1. Boot 4 下 Spring Cloud Gateway starter 已改名，旧名 `spring-cloud-starter-gateway` 失效。
     - 响应式(Netty)：`spring-cloud-starter-gateway-server-webflux`
     - Servlet(Tomcat，与现有 service-* 一致，本项目选用)：`spring-cloud-starter-gateway-server-webmvc`，版本 **5.0.3**（属 Spring Cloud 2025.1.x，适配 Boot 4.0.x）。
     - 路由配置根也变为 `spring.cloud.gateway.server.webmvc.routes`（不再是 `spring.cloud.gateway.routes`）。
  2. 本地离线仓库没有 gateway / spring-cloud-dependencies BOM，需联网 `mvnw package` 从 Maven Central 下载 5.0.3（网络可用，实测 200）。
  3. 未接 Nacos，`uri` 写死 `http://localhost:8081` / `:8082`；接注册中心后改 `lb://service-name`。
- 文件：service-gateway/pom.xml（web + gateway webmvc:5.0.3 + lombok optional）、GatewayApplication(@SpringBootApplication)、application.yml（port 8080 + 两条路由）。父 pom <modules> 加 service-gateway。
- 验证：mvnw -pl service-gateway -am package → BUILD SUCCESS；端到端启动网关+service-system，`GET :8080/api/sys-user/list` → 200（透传后端返回的 `[]`）。
- 沙箱运行注意：本机 shell 设了 `SERVER_PORT` 环境变量，会覆盖 application.yml 的 server.port，导致多实例抢同一端口（实测都绑到 60584 互相冲突）。本地 `java -jar` 演示需显式加 `--server.port=8080/8081` 覆盖。用户自己的机器通常无此变量，yml 端口即生效。
- 工具链注意：本环境 Bash 运行时损坏（dirname/cd/head not found，curl 也起不来）；PowerShell 的 `Start-Process` 带 `-RedirectStandard*` 会触发 Path/PATH 大小写冲突报错，改用 `--logging.file.name` 写日志、`--server.port` 显式端口即可绕过。`cmd.exe` 与 `Start-Job -ScriptBlock` 被安全策略拦截，不可用。
